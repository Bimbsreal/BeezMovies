# Catalog schema

PostgreSQL is the source of truth for the BeezMovies catalog. Search indexes, Redis, worker state, and CDN copies are derived. They must not become the movie database.

Binary media is not stored in PostgreSQL. Images, trailers, and playback entries are URLs or external references.

## Lifecycle

Movie `status` is only `draft`, `active`, or `archived`. Archiving sets `archived_at`. Important catalog rows use `ON DELETE RESTRICT`, so removing a movie, person, provider, or source fails while dependents exist. Deactivate or archive instead of cascading deletes.

## Provider abstraction

`providers` describes a media or metadata provider. `media_references` points at authorized media through `provider_id` plus `external_reference`. There is no table per vendor.

`providers.configuration` is non-secret JSON. API credentials stay in server environment configuration. A check rejects common secret key names at the top level of that JSON.

`catalog_sources` names a metadata origin. `external_identifiers` maps one external id from one source to one movie, and one id per source on a movie.

Trailer rows in `movie_videos` are metadata references. They are not provider integrations.

## Relationships

```
Movies
 ├── Genres            movie_genres
 ├── Languages         movie_languages, movies.original_language_id
 ├── Countries         movie_countries
 ├── People/Credits    movie_credits → people
 ├── Alternate Titles  alternate_titles
 ├── Ratings           movie_ratings
 ├── Tags              movie_tags
 ├── Images            movie_images
 ├── Trailers          movie_videos
 ├── Collections       collection_movies → collections
 ├── External IDs      external_identifiers → catalog_sources
 └── Media References  media_references
          │
          ▼
       Providers
```

A movie belongs to at most one collection. Credit `department` and `job` are open text so later credit types do not need a new table.

`original_language_id` is the film's original language. `movie_languages` lists spoken languages. Those are different facts.

`release_date` is the full date when known. `release_year` supports year-only records and duplicate matching. When both are set, the year must match the date.

`normalized_title` and `normalized_name` are generated by folding letters and digits to lowercase. That is the current duplicate-matching signal, together with release year, runtime, external ids, alternate titles, and credits. There is no deduplication service yet.

## Indexes

Unique indexes cover slugs and external identifiers. Additional btree indexes cover titles, normalized titles, release date, release year, status, foreign keys, and active movies by release date. The derived search index in [search.md](search.md) adds full-text and trigram indexes on `search_documents`. Those indexes are not a second catalog.

## Migrations and seed

| File | Contents |
| --- | --- |
| `001_foundation.sql` | Readiness marker |
| `002_catalog_core.sql` | Languages, countries, genres, tags, people, sources, providers, collections, movies |
| `003_catalog_relationships.sql` | Titles, credits, junctions, identifiers, ratings |
| `004_catalog_media.sql` | Images, videos, media references |
| `005_catalog_indexes.sql` | Lookup indexes |

`npm run migrate` applies those files in order inside transactions.

`npm run seed` loads `database/seeds/001_catalog_dev.sql` after migrating. The seed is development data: public-domain film examples and `example.com` placeholder references. It does not run in production.

## Decisions

- Primary keys are UUID v4 from `gen_random_uuid()` so PostgreSQL 16 remains valid. UUID v7 is available on PostgreSQL 18 and can be adopted later.
- Controlled states use `CHECK` constraints rather than enum types, so a later state can be added inside a normal migration transaction.
- Title normalization is an ASCII fold. Accented characters are not transliterated.
